# Verification

The alpha's supported claim is narrow: selected Python tests can distinguish a
known pre-fix Git commit from a fix. This record separates local observations
from broader product claims. The project does not yet have independent user
adoption evidence.

## Local product checks

Test host: Windows 11 build 26200, CPython 3.12.14, 2026-09-27. The source
suite exercises positive and negative verdicts, pytest and unittest, skipped
tests, runtime errors, timeouts, input mutation, repeated-run instability,
test-only changes, and checkout preservation. The packaged wheel was installed
in a separate virtual environment and invoked outside the source tree.

| Check | Observed result |
| --- | --- |
| [Source suite on the alpha source](evidence/alpha-source-tests.txt) | 20 tests passed |
| Installed wheel smoke check | `bugbix --version` returned `Bugbix 0.4.0a1` |
| Package consistency | Wheel Python source bytes matched the files in this repository |

The installed `0.4.0a1` wheel was also replayed locally on the boltons byte
write-count regression. It returned `regression_observed` with two assertion
failures before and two passes after the fix. The same wheel returned
`not_demonstrated` for the existing more-itertools control test, which passed
on both sides.

## Public GitHub repository trials

These were our local runs of other contributors' merged tests and fixes. Each
side ran twice in a fresh snapshot. Bugbix did not modify the source checkouts.
The exact upstream commits, test selectors, and command results are listed so
the comparisons can be repeated. The full raw snapshot logs remain local; they
are not included in this repository because they contain machine-specific paths
and copies of the upstream projects.

| Project | Before and after | Selected test result |

The humanize blocker is a real setup limit. Its version module is generated by
the project's build system. Installing test dependencies alone did not resolve
it. Bugbix names the missing module in the report rather than treating a setup
error as a successful regression check.

## Reproduce the product suite

```sh
python -m pip install pytest
python -m unittest discover -s tests -v
python -m pip wheel --no-deps --wheel-dir dist .
```

The GitHub Actions workflow runs the suite on Windows and Ubuntu with Python
3.12. A passing workflow is separate evidence from the local results above;
check the latest run before assuming either platform passed remotely.

## Boundaries

Only Windows and Python 3.12 have been verified locally. The third-party runs
were focused tests, not complete upstream test suites. The two successful
projects demonstrate technical utility, not demand. Generated files, external
services, untracked prior baselines, and other languages remain outside this
alpha's verified scope. Test code runs with the caller's permissions; the
snapshot directories are not a security sandbox.
